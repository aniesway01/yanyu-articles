一、客户分类：从就诊阶段出发

客户按就诊阶段分为四种类型。这是客户自身的状态，决定了他们的核心需求。

Type 1

一片白纸 — 未确诊，纯询问

还没看医生或刚有疑似症状，纯粹来了解保险能做什么。

核心需求：科普、了解保险能起什么作用

Type 2

已就医未确诊 — 想知道保单能起什么作用

已经看过医生但还没确诊，想提前了解自己的保单在未来可能派上什么用场。

核心需求：保障评估、就医注意事项（医院资质、诊断书要求）

Type 3

确诊且用药中 — 想知道能不能报销

已经确诊并在用药，想知道当前药物能不能报销，或者保单对自己的疗程有什么好处。

核心需求：药物匹配、理赔申请、特药直付

Type 4

确诊但被拒赔 — 需要申诉帮助

已经确诊并申请过理赔，但被保险公司拒绝了。

核心需求：拒赔分析、申诉指导、救济渠道

二、接待维度：从我们的角度

不管客户属于 Type 1~4 哪种，从我们接待的角度只有三种情况：

接待阶段说明
第 1 次见面初次接触，建立信任，收集基本信息
第 2 次见面回访跟进，反馈评估结果
第 N 次见面长期客户，持续服务

交叉矩阵

两个维度交叉后，形成完整的服务地图：

第 1 次见面 第 2 次见面 第 N 次见面
Type 1 白纸 科普 + 收集基本信息 反馈权益评估：告知保单覆盖范围、就医注意事项；引导投保（若未投保） 保单到期提醒 + 续保引导；定期推送健康权益（洁牙、癌筛等增值服务）
Type 2 已就医未确诊 保障评估 + 就医指导 跟进就医进展：确诊了吗？诊断书内容是否符合理赔要求？提前规划材料准备方向 持续关注病情发展；确诊后自动升级为 Type 3 服务；推送相关权益
Type 3 确诊+用药 药物匹配 + 材料准备 反馈 TPA 沟通结果：哪些能报、需要补什么材料；预审材料后指导客户提交保司 追踪理赔进度 + 结果解读；疗程变更时重新评估；到期推荐续保/复发险
Type 4 被拒赔 拒赔分析 + 情绪安抚 反馈申诉方案：补充材料清单、医生情况说明、申诉路径（保司申诉/消保投诉/仲裁） 跟踪申诉进度；推送同病种理赔成功案例；政策变动时主动通知
💡 核心逻辑：第 1 次建立信任、收集信息；第 2 次反馈专业评估结果（体现价值）；第 N 次持续跟踪 + 主动推送（建立长期依赖）。

三、后台运行流程

接待客户之后，后台的运作方式：

客户提交资料给我们 │ ▼ 我们跟 TPA（第三方管理机构）沟通 → 确认能不能核销 │ ▼ 给客户答复 → 告知哪些能报、哪些不能、需要补什么 │ ▼ 客户根据我们的意见准备/整理申请材料 │ ▼ 客户提交材料给保司 │ ▼ 等保司审核结果 ├─ 通过 → 理赔成功 └─ 拒绝 → 回到我们，进入申诉流程
关键定位：我们不是直接帮客户提交给保司，而是在中间做「预审 + TPA 沟通」的角色，确保客户提交的材料和方向是对的。

四、角色定位

  • 我们是咨询公司，不是法律公司，不是保险公司
  • 核心价值：帮保户最大化理赔成功率，降低因不懂规则导致的拒赔
  • 长期目标：成为保户的健康管理代办，每次报销前帮他复核一遍
